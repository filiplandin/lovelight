How the user gets a Light API key:
- Navigate to https://app.light.inc/settings/api-keys
- Click "Create Key"
- Name it (e.g., "Lovable Dashboard")
- Assign role: Controller (read-only) or AR Clerk (if write access needed)
- Click Create and copy the key
DOMAIN: Invoice Receivables (Sales Invoices)
Light API Documentation: https://light.inc/docs/getting-started/introduction
For complete API reference including request/response schemas, authentication, rate limits, and examples,
visit the docs. The full API index is at: https://light.inc/docs/llms.txt
Key endpoints for Invoice Receivables:
- List invoices: GET https://api.sandbox.light.inc/rest/ext/v1/invoice-receivables
- Get invoice by ID: GET https://api.sandbox.light.inc/rest/ext/v1/invoice-receivables/{invoiceId}
- Get invoice payments: GET https://api.sandbox.light.inc/rest/ext/v1/invoice-receivables/{invoiceId}/payments
- Create invoice: POST https://api.sandbox.light.inc/rest/ext/v1/invoice-receivables
- Update invoice: PATCH https://api.sandbox.light.inc/rest/ext/v1/invoice-receivables/{invoiceId}
- Record payment: POST https://api.sandbox.light.inc/rest/ext/v1/invoice-receivables/{invoiceId}/payments
STATE MANAGEMENT endpoints (use with extreme caution - DESTRUCTIVE):
- Open invoice: POST https://api.sandbox.light.inc/rest/ext/v1/invoice-receivables/{invoiceId}/open (assigns number, locks editing, may send emails)
- Archive invoice: POST https://api.sandbox.light.inc/rest/ext/v1/invoice-receivables/{invoiceId}/archive
- Reset invoice: POST https://api.sandbox.light.inc/rest/ext/v1/invoice-receivables/{invoiceId}/reset (reverts to draft)
Critical warnings:
- State management operations are DESTRUCTIVE and affect revenue recognition
- These have tax and accounting implications - only implement if explicitly requested
- Opening an invoice locks it; use reset to revert to draft
- Recording payments auto-updates state to PARTIALLY_PAID or PAID
Best practices:
- Use X-Idempotency-Key header for write requests (recommended)
- Only implement write/state operations if user explicitly requests them
- Auth: Authorization: Basic <LIGHT_API_KEY> (server-side only)
Current Light UI filter: state:in:DRAFT|OPEN|PARTIALLY_PAID|CREATED|OPEN_IN_PROGRESS|PAYMENT_PENDING
Current Light UI sort: createdAt:desc
